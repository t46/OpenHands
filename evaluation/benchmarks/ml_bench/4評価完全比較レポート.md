## 2. 退行分析：なぜ成功していたタスクが失敗したのか

### 2.1 Dec 2で成功 → Dec 4 (修正後)で失敗したタスク（5件）

#### 📌 Task 3: Enhanced Super-Resolution GAN (PyTorch-GAN)
- **Exit Code変化**: 124 (タイムアウト成功) → -1 → -1 (タイムアウト失敗)
- **原因**: ⏱️ **タイムアウトタイミングの変化**
- **詳細**:
  - Dec 2では120秒以内に一定の進捗があり、Exit 124で成功扱い
  - Dec 4では同じ時間内に進捗が不足し、Exit -1で失敗
  - エージェントの行動順序の微妙な違いによる
- **対策**: タスク実行の効率化、または初期化の最適化

#### 📌 Task 16: Softmax GAN (PyTorch-GAN)
- **Exit Code変化**: 124 → 124 → 2 (Bashシンタックスエラー)
- **原因**: 🔄 **インストラクション変更の悪影響**
- **詳細**:
  - エラー: `python: can't open file '/workspace/PyTorch-GAN/softmax_gan.py': [Errno 2] No such file or directory`
  - Dec 2とDec 4前ではタイムアウトで成功扱い
  - Dec 4後でBashスクリプトの書き方が変わり、ファイルパスエラーが露呈
- **対策**: このタスクは元々不安定。Exit 2の残り1件として要調査

#### 📌 Task 77: BLIP-2 T5 Caption (lavis)
- **Exit Code変化**: 0 (正常完了) → 2 → -1
- **原因**: 🐛 **エージェント非決定性による実装の変化**
- **詳細**:
  - Dec 2では正しく完了
  - Dec 4前でBash構文エラー（Pythonコード混入）
  - Dec 4後でタイムアウト失敗（モデルダウンロードに時間がかかる）
- **対策**: モデルの事前ダウンロード、またはタイムアウト最適化

#### 📌 Task 85: BLIP Feature Extraction (lavis)
- **Exit Code変化**: 0 → -1 → -1
- **原因**: 🐛 **エージェント非決定性によるタイムアウト**
- **詳細**:
  - Dec 2では正常完了
  - Dec 4以降はモデルロードに時間がかかりタイムアウト
  - エージェントの実装アプローチの違い
- **対策**: モデルキャッシュの改善

#### 📌 Task 121: edge2face (vid2vid)
- **Exit Code変化**: 0 → 0 → 1 (スクリプトエラー)
- **原因**: 🐛 **コンパイルエラー（環境依存の可能性）**
- **詳細**:
  - C++コンパイルエラーが発生
  - Dec 2とDec 4前では成功していたため、環境の微妙な違いか実装の違い
- **対策**: コンパイル依存関係の明示化

### 2.2 Dec 4 (修正前)で成功 → Dec 4 (修正後)で失敗したタスク（3件）

これらは**インストラクション変更の直接的な影響**を受けたタスク

#### 📌 Task 129: edge2face Training (vid2vid)

- **対策**: 依存関係の事前インストール

#### 📌 Task 272: Grounding DINO Demo (Grounded-Segment-Anything)
- **Exit Code変化**: -1 → 0 → -1

## 5. 非決定性の影響分析

### 5.1 Temperature=0.0でも発生する非決定性

**設定**:
- Temperature: 0.0（完全に決定的なはず）
- モデル: Claude Sonnet 4.5
- 環境: 完全に同一（Git commit、Docker image）

**観測された非決定性**:
- Dec 2 → Dec 4前: 13件退行、5件改善
- Dec 4前 → Dec 4後: 15件改善、5件退行（インストラクション変更あり）

### 5.2 非決定性の影響を受けやすいタスク

**特徴**:
1. **タイムアウトギリギリ**: 実行時間が120秒前後
2. **外部依存**: モデルのダウンロード、依存関係のインストール
3. **複雑な手順**: 多段階のセットアップが必要
4. **エラー処理**: エラーからのリカバリーパスが複数ある

**該当タスク例**:
- Task 3, 77, 85, 101, 129, 272（すべてタイムアウト関連）

### 5.3 非決定性への対応策

1. **短期**:
   - 複数回実行して最良の結果を採用
   - タイムアウトの最適化

2. **中期**:
   - エージェントプロンプトの改善
   - 決定的な実行パスの強化

3. **長期**:
   - モデルレベルでの決定性の向上
   - 環境のさらなる標準化
